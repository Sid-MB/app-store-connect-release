# App Store Connect Release

Publish a GitHub release from an existing version tag as soon as App Store Connect reports that the matching app version is `READY_FOR_DISTRIBUTION`.

The project contains:

- A reusable GitHub workflow and JavaScript Action that work with public or private application repositories.
- A Cloudflare Worker that authenticates App Store Connect webhooks and forwards only release-worthy events.
- An interactive setup CLI that configures GitHub, Cloudflare, and App Store Connect from inside an application repository.

## One-command setup

### Prerequisites

- Node.js 22 or newer.
- [GitHub CLI](https://cli.github.com/) installed and allowed to administer the target repository.
- `curl`.
- A Cloudflare account. Wrangler is bundled as a runtime dependency, so a global installation is not required.
- An App Store Connect user with the Account Holder, Admin, or App Manager role.

From the Git repository that should receive releases, run:

```sh
npx --yes --package=github:Sid-MB/app-store-connect-release#v1 asc-release setup
```

The CLI prompts for one value at a time and explains where to obtain it. It:

1. Identifies the current GitHub repository and its default branch.
2. Helps you create either an App Store Connect team API key with App Manager access or an individual API key owned by an App Manager or higher.
3. Infers the Key ID from Apple's standard `AuthKey_<KEY_ID>.p8` filename, prompts only when the file was renamed, validates the private key locally, and lists the apps available to it.
4. Provides a prefilled GitHub fine-grained token URL and asks you to restrict the token to the current repository with `Contents: write`.
5. Prompts for a Cloudflare Worker name with the default `<repository>-appstoreconnect-webhook-receiver`, signs in to Cloudflare using the bundled Wrangler CLI, deploys the isolated Worker, and uploads its secrets.
6. Stores the Apple API credentials as GitHub Actions secrets.
7. Verifies GitHub dispatch access and the Worker's public health endpoint.
8. Creates or updates the matching App Store Connect webhook through `POST /v1/webhooks` or `PATCH /v1/webhooks/{id}`.
9. Requests Apple's signed Ping delivery, retrying transient failures up to three times.
10. Only after every preceding step succeeds, commits `.github/workflows/app-store-connect-release.yml` directly to the default branch if it does not already exist.

Rerunning setup is safe: it redeploys the same Worker, rotates its Apple webhook secret, updates the matching webhook, replaces the GitHub secrets, and does not duplicate the listener workflow. If setup fails before the final step, the workflow file is not committed.

## What happens on release

```text
App Store Connect
  └─ signed APP_STORE_VERSION_APP_VERSION_STATE_UPDATED
      └─ Cloudflare Worker verifies x-apple-signature
          └─ newValue == READY_FOR_DISTRIBUTION
              └─ GitHub repository_dispatch
                  └─ reusable workflow reads versionString from Apple
                      └─ verifies tag v<version> already exists
                          └─ creates the GitHub release
```

The webhook does not include the marketing version string. It contains an `appStoreVersions` resource ID, so the Action uses the App Store Connect API key to read `versionString` and `platform`. It then:

- Resolves the tag using `v{version}` by default.
- Fails safely if the tag does not already exist; it never creates or moves tags.
- Treats replayed webhook deliveries and concurrent runs idempotently.
- Prepends authenticated App Store event metadata to GitHub-generated release notes.
- Uses the target repository's short-lived `GITHUB_TOKEN` to create the release.

Repositories in this account currently use tags like `v2.0.0`, which match the default template. A repository using another convention can change `tag-template` in its caller workflow.

## Secrets and where they belong

These are separate credentials for separate trust boundaries.

### Cloudflare Worker secrets

| Name | Set by | Purpose |
| --- | --- | --- |
| `APPLE_WEBHOOK_SECRET` | Generated by the CLI | HMAC-SHA256 secret shared only with the matching App Store Connect webhook. |
| `GITHUB_DISPATCH_TOKEN` | Pasted during setup | Fine-grained token restricted to the target repository with `Contents: write`; used only for `repository_dispatch`. |

The Worker also receives the non-secret `GITHUB_REPOSITORY=owner/repository` variable. Neither secret belongs in source control or in the target repository's Actions secrets.

The CLI lets you choose the Worker name. Its default is `<repository>-appstoreconnect-webhook-receiver`, shortened when necessary to meet the 63-character `workers.dev` DNS-label limit. Custom names are normalized to lowercase before deployment.

### Target GitHub repository secrets

| Name | Required | Purpose |
| --- | --- | --- |
| `APP_STORE_CONNECT_KEY_ID` | Yes | Identifies the `.p8` API key. |
| `APP_STORE_CONNECT_PRIVATE_KEY` | Yes | Signs short-lived App Store Connect API JWTs. |
| `APP_STORE_CONNECT_ISSUER_ID` | Team keys only | Team-key issuer. Individual keys omit this because Apple requires `sub: user` instead. |

The Apple private key is not sent to Cloudflare. The Action reads it only inside the target repository's workflow run.

### GitHub workflow token

The reusable workflow uses the target repository's automatic `GITHUB_TOKEN` with only:

```yaml
permissions:
  contents: write
```

That token expires with the workflow job and is not stored anywhere.

## Manual setup

The CLI is recommended, but every step can be performed manually.

### 1. Create an App Store Connect API key

Open [App Store Connect API integrations](https://appstoreconnect.apple.com/access/integrations/api).

For a team key:

- Generate a key with **App Manager** access.
- Copy its Issuer ID.
- Download the `.p8` private key.

For an individual key:

- The associated user must be Account Holder, Admin, or App Manager.
- Open the user profile and generate the Individual API Key.
- Download the `.p8` file.
- Do not configure an issuer ID; individual JWTs use `sub: user`.

The CLI reads the Key ID from Apple's standard `AuthKey_<KEY_ID>.p8` filename. If the file has been renamed, it asks you to paste the Key ID as a fallback.

Apple makes private keys downloadable only once. Keep the file secure and revoke it immediately if it is exposed.

Add the values to the target GitHub repository under **Settings → Secrets and variables → Actions** using the names in the table above.

### 2. Create the Worker dispatch token

Create a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new?name=App+Store+release+dispatch&description=Dispatch+authenticated+App+Store+events&expires_in=90&contents=write):

- Select the owner of the target repository.
- Choose **Only select repositories** and select that repository.
- Grant **Contents: Read and write**.
- Do not grant account or organization permissions.

GitHub currently requires `Contents: write` for the repository dispatch endpoint even though the Worker does not modify repository contents.

### 3. Deploy the Worker

Clone this repository, edit `worker/wrangler.jsonc`, and replace `owner/repository`:

```sh
npx wrangler login
npx wrangler deploy --config worker/wrangler.jsonc
npx wrangler secret put APPLE_WEBHOOK_SECRET --config worker/wrangler.jsonc
npx wrangler secret put GITHUB_DISPATCH_TOKEN --config worker/wrangler.jsonc
```

Generate `APPLE_WEBHOOK_SECRET` with:

```sh
openssl rand -hex 32
```

Enter exactly the same generated value into App Store Connect. Do not reuse it for another app.

### 4. Configure App Store Connect

In **Users and Access → Integrations → Webhooks**, create a webhook with:

| Form field | Value |
| --- | --- |
| Name | `GitHub release: owner/repository` |
| Payload URL | The HTTPS `workers.dev` URL printed by Wrangler |
| Secret | The exact value stored as `APPLE_WEBHOOK_SECRET` |
| App | The app represented by this GitHub repository |
| Event trigger | App Store version app-version-state updates (`APP_STORE_VERSION_APP_VERSION_STATE_UPDATED`) |

The equivalent API request is:

```json
{
  "data": {
    "type": "webhooks",
    "attributes": {
      "enabled": true,
      "eventTypes": ["APP_STORE_VERSION_APP_VERSION_STATE_UPDATED"],
      "name": "GitHub release: owner/repository",
      "secret": "the same APPLE_WEBHOOK_SECRET stored in Cloudflare",
      "url": "https://your-worker.your-subdomain.workers.dev"
    },
    "relationships": {
      "app": {
        "data": {
          "type": "apps",
          "id": "your App Store Connect app resource ID"
        }
      }
    }
  }
}
```

Send that body to `POST https://api.appstoreconnect.apple.com/v1/webhooks` with a short-lived App Store Connect JWT.

### 5. Install the caller workflow

Copy [`examples/caller-workflow.yml`](examples/caller-workflow.yml) to `.github/workflows/app-store-connect-release.yml` on the target repository's default branch. GitHub only triggers `repository_dispatch` workflows that exist on the default branch.

If the target repository restricts third-party Actions, allow:

```text
Sid-MB/app-store-connect-release@*
```

### 6. Test

Open the webhook in App Store Connect and select **Test**. A signed Ping should show as successful. The Worker acknowledges Ping and all authenticated non-release events without dispatching the release workflow.

## Customization

The caller workflow can configure:

```yaml
with:
  payload-json: ${{ toJSON(github.event.client_payload) }}
  tag-template: release/{version}
  release-name-template: Version {version} for {platform}
```

Supported placeholders:

- `tag-template`: `{version}`
- `release-name-template`: `{version}`, `{tag}`, `{platform}`

GitHub uses `.github/release.yml` or `.github/release.yaml` in the target repository when generating changelog notes, so each app can customize categories and excluded labels without changing this Action.

## Security model

- Apple signs the exact raw request body using HMAC-SHA256 and sends `x-apple-signature: hmacsha256=<hex>`.
- The Worker rejects unsigned or modified payloads before parsing them.
- The Worker returns an error when GitHub rejects a dispatch, allowing the delivery to appear as failed and be resent from App Store Connect.
- Apple can resend the same event ID, so releases are keyed by the existing tag and duplicate creation is treated as success.
- Each app gets a separate Worker, webhook secret, and repository-scoped dispatch token.
- The Worker never receives the App Store Connect private key.
- The Action never creates or moves Git tags.

## Development

```sh
npm install
npm run check
```

`npm run build` bundles the Node 24 Action into `dist/action/index.js` and the interactive CLI into `cli/dist/index.js`. Built artifacts are committed because GitHub Actions and `npx --package=github:…` execute repository contents directly.
